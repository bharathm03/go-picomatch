# tools/mutate — what the fixtures cannot see

```bash
make mutate          # report and gate
node tools/mutate/run.js --json
```

## The question

`make conformance` answers "how much of upstream's recorded behaviour does the
port reproduce?" It cannot answer the question behind it: **is reproducing all of
it enough?**

A fixture set proves a port correct only for behaviour it actually exercises.
picomatch's suite is 1,977 tests and 20,930 recorded behaviours, which sounds
exhaustive — and is, structurally. It explores braces, extglobs, globstars,
brackets, negation and slashes in enormous depth. It explores **91 distinct code
points**, from U+0009 to U+30EB, four of them non-ASCII. It is a structural
corpus, not an alphabetic one, and nothing in a parity percentage says so.

## The method

Take upstream picomatch, apply a mutation a Go port would plausibly make, and
replay every fixture against the mutant. Fixtures that now fail have *detected*
the mutation. A mutation nothing detects is behaviour the fixture set is blind
to — a port could ship it and every number in this repo would still read clean.

`replay.js` mirrors `conformance_test.go`'s comparison exactly: the same four
APIs, the same fields, `match` and `regex` skipped just as
`matcherFieldsNotCompared` declares. Measuring a stricter comparison than the one
that actually runs would describe a harness that does not exist.

## Why every mutation carries a witness

A mutation that changes no behaviour survives every fixture and looks exactly
like a coverage hole. This is not hypothetical — making `*` greedy instead of
lazy survives all 18,792 fixtures, and means nothing: in an anchored pattern,
greedy and lazy accept the same language and differ only in capture positions,
which are not compared. It was mistaken for a finding, then removed.

So each mutation declares witnesses: pattern/input pairs where base and mutant
must give different answers. The harness evaluates them in a child process
against both trees, and refuses to report a survival until at least one witness
diverges. A no-op mutation fails the run rather than being counted as a hole.

The same guard caught a bad witness on a real mutation: `?` against `".a"` cannot
discriminate a missing dot guard, because the lengths differ and both readings
answer `false`. The witness is now `"."`.

## Results

Two controls, five holes. Every hole is a case where the *idiomatic* Go code is
the wrong code:

| Mutation | upstream | charaxis |
| --- | ---: | ---: |
| *control:* drop the dot guard from `?` | 29 | 0 |
| *control:* drop the `input === glob` shortcut | 34 | 0 |
| walk by rune, not UTF-16 code unit | **0** | 20 |
| `nocase` via Unicode folding | **0** | 8 |
| globstar body as "any character" | **0** | 14 |
| `maxLength` counted in code points | **0** | 4 |
| no inline fastpaths | **0** | 6 |

`for i, r := range s` is *the* idiomatic Go string walk and it decodes runes.
`len(s)` is bytes, `len([]rune(s))` is code points, and picomatch counts UTF-16
units — for `"😀"` that is 4, 1 and 2. All three differ and no upstream fixture
prefers one. `(?i)` and `unicode.ToLower` both fold U+212A onto `k`; JavaScript's
non-unicode `Canonicalize` explicitly refuses to fold non-ASCII onto ASCII.

The `charaxis` column is `testdata/charaxis`, generated by
`tools/charaxis/generate.js` for exactly these five holes. That it kills all five
is checked here on every run, not assumed.

## Exit status

Non-zero when:

- a mutation marked `expected: 'killed'` survives — the fixtures lost coverage
  they used to have;
- a mutation is a no-op, so its result is meaningless;
- a mutation survives **every** fixture set — a live hole with nothing watching it.

A mutation marked `survives` that starts being killed is reported as an
improvement, not a failure; update `expected` in `mutations.js`.

## What it never touches

`tests/original` is hash-pinned by `MANIFEST.json` and is only ever read. Every
edit lands in a copy under the system temp directory, removed when the run ends.
`make check` still runs `verify-original` afterwards.
